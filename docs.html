Section 2

Scripts, globals & load order

The bridge mutates the DSA_* globals in place, so everything reading them must load after it. data-strategy-guides.js uses ||-guards, so it must load before the bridge or its seed data is skipped.

main.js → data files (data-units.js, data-matchups.js, data-tierlist.js, data-strategy-guides.js, …)
        → data-community-additions.js → community-data-bridge.js → page scripts

main.js

Defines window.DSA: escapeHTML, raceClass, tierClass, label, renderList, filled, navItems, toolCards, noobTraps, beginnerLessons, glossaryEntries. Renders nav, footer, settings panel, tool cards, noob-trap detector, lessons, glossary.

community-data-bridge.js

Merges shipped snapshot ⊕ server cache ⊕ local patches, then overwrites DSA_THREAT_RESPONSES, DSA_GENERAL_MATCHUPS, DSA_TIERLIST, DSA_UNITS, DSA_STRATEGY_GUIDES, DSA_RACE_GUIDES, DSA_WORST_BUILDS, DSA_ADMIN_USERS. Exposes DSA_APPLY_COMMUNITY_ADDITIONS, DSA_GET_COMMUNITY_DATA, DSA_FORCE_PUBLIC_BACKEND_SYNC.

Data files (no DOM)

data-matchups.js → DSA_GENERAL_MATCHUPS / DSA_THREAT_RESPONSES / DSA_THREAT_SORTING / DSA_ALL_THREAT_UNITS. data-units.js → DSA_UNITS. data-tierlist.js → DSA_TIERLIST. data-strategy-guides.js → DSA_STRATEGY_GUIDES + DSA_RACE_GUIDES. data-quizzes.js → DSA_GAS_SCENARIOS + DSA_ZVZ_SCENARIOS. data-admin-schema.js / data-admin-users.js → admin dropdowns and login hints.

matchup-helper.js

Filters threats by myRace / enemyRace / positionContext, hides rows without a useful response, sorts by sortScore. Exposes DSA_MATCHUP_HELPER_REFRESH(); listens to community events and cross-tab storage changes. Reads ?race= / ?enemy= URL params.

strategy-spotlight.js + worst-builds.js

Sidebar spotlight: 3 random guides for the selected race, enemy-relevant first, shuffle button. Worst builds: one fetch of /api/admin/worst-builds, rotating top-3 card, submit/vote modal, static DSA_WORST_BUILDS fallback.

Other page scripts

start.js (funnel), tier-list.js, unit-counter.js, strategy-database.js, race-guides-page.js, gas-trainer.js, zvz-trainer.js, wave-animation.js (mountWaveAnimation()), wave-function-page.js, admin.js (full panel, Bearer-token API calls), visit-router.js (redirect only).

Section 3

Data schemas

Generated from the fill-in xlsx workbook. Blank cells are supported everywhere: rows without content render "Not filled yet." or are hidden via hasResponse.

DSA_THREAT_RESPONSES — the helper's core dataset

Key fields: enemyThreat, unitRace (threat's race), myRace, enemyRaceContext/positionContext ('Any' or specific), priority, skillCap, counterUnits[] (first 3 shown), responseText, scoutTiming, responseTiming, avoid[], warning, notes, hasResponse, sortScore (ordering), importance.

{ "id": "lurker__zerg", "enemyThreat": "Lurker", "unitRace": "Zerg", "myRace": "Zerg",
  "enemyRaceContext": "Any", "positionContext": "Any", "skillCap": "High", "priority": "Critical",
  "counterUnits": ["Corruptor", "Lurker", "Queen"],
  "responseText": "One of the main zerg mechanics is whoever has more lurkers wins...",
  "warning": "Don't build if your team is actively losing air...",
  "hasResponse": true, "sortScore": 220, "importance": "Critical" }

DSA_GENERAL_MATCHUPS

One row per myRace × enemyRace × position (27 rows): title, overview, priorities[], positionNote, confidence.

DSA_UNITS & DSA_TIERLIST

Units: name, slug, image, race, tier/earlyTier/lateTier/oldTier/newTier, role, summary, skillLevel, strongAgainst[], weakAgainst[], commonMistake, beginnerWarning. Tier list mirrors the same units with unit, notes, confidence.

DSA_STRATEGY_GUIDES & DSA_RACE_GUIDES

Guides: id, title, race (or 'Any'), matchup, category, summary, body, tags[], author, updatedAt. Race-page sections add page ('tvt'|'pvp'), order, keyPoints[], commonMistakes[], optional quizQuestions[] (max 3).

Quizzes

DSA_GAS_SCENARIOS: { title, prompt, correct: 'Yes'|'No', explanation }. DSA_ZVZ_SCENARIOS: { title, prompt, options[], correct, explanation }. Plain objects so non-programmers can edit.

Community store envelope (DSA_COMMUNITY_ADDITIONS)

{ "version": 6, "generatedAt": "ISO", "generatedBy": "isaac",
  "changelog": [{ changeId, timestamp, editorId, editorName, editorRole, scopeRace, dataset, action, target, note }],
  "users":     { "patches": [], "deleted": [] },
  "patches":   { "threatResponses": [{ targetName, after: {...} }], "tierList": [], "units": [], "generalMatchups": [] },
  "additions": { "threatResponses": [], "communityGuides": [], "feedback": [], "raceGuides": [], "worstBuilds": [] } }

patches update existing rows by compound key (threat: myRace|enemyRaceContext|positionContext|enemyThreat); additions are append-only, deduped by id. Worst builds carry votes: { up, down } and sort by net votes.

Section 4

Admin / community pipeline

Admin saves go to Netlify Blobs through serverless functions; public pages run on the shipped static snapshot plus a throttled hourly sync.

admin.html (admin.js)
  → POST /api/admin/auth   (server-checked password, token in DSA_ADMIN_SESSION_V3)
  → POST /api/admin/change (writes Netlify Blobs) + mirror to localStorage DSA_COMMUNITY_PATCHES_V3

public page load:
  data files → data-community-additions.js (shipped snapshot)
  → community-data-bridge.js: merge shipped ⊕ server cache ⊕ local patches
      → overwrite DSA_* globals → event 'dsa-community-data-ready'
  → GET /api/admin/public (≤ once/hour/browser)
      → re-apply → event 'dsa-community-server-data-ready'
refresh hooks: pages listen to both events; the helper also exposes
  DSA_MATCHUP_HELPER_REFRESH() and watches cross-tab 'storage' changes.

Netlify function routes

netlify/functions/dsa-admin.mjs (esbuild, @netlify/blobs): GET /api/admin/public · POST /auth · GET /state · POST /change · POST /users · GET /login-users · GET /export-js | export-json | export-md · POST /clear · GET /worst-builds · POST /worst-builds/submit · POST /worst-builds/vote.

Permissions

Enforced server-side: owner (all), race-editor (own race's threat/tier/guides; Terran→tvt and Protoss→pvp pages only), reviewer (guides + feedback). Env vars: DSA_OWNER_PASSWORD_HASH (npm run hash:password), DSA_SESSION_SECRET.

Throttle / low-credit mode

Public sync ≤ 1×/hour per browser. Force: ?syncCommunity=1. Disable: localStorage DSA_DISABLE_PUBLIC_BACKEND_SYNC='true'. Cheapest publish: export data-community-additions.js from admin and redeploy the static file. Details: NETLIFY_*.md in repo root.

Section 5

Conventions

Escaping

Every user/data string goes through DSA.escapeHTML (page scripts alias it as esc() with a local fallback). Never interpolate raw data into innerHTML.

Unit images

slug(name) → assets/units/<slug>.png with onerror fallback to assets/units/unknown.png. matchup-helper.js adds typo aliases (pheonix→phoenix, mutalisk→muta, sigetank→siege-tank…).

Badge classes

Races: race-zerg / race-terran / race-protoss. Tiers: tier-s…tier-f. Priority: priority-critical / high / medium / low. Skill: skill-very-high / high / medium / low.

Layout

--max CSS var controls page width (1180px default; body.matchup-wide → 1520px). .matchup-layout = grid minmax(280px,1fr) / minmax(0,2fr); sidebar sticky, hidden under 1100px. The container::before background gradient also keys off --max.

Empty data

Blank workbook cells are normal: render "Not filled yet." via DSA.filled, or hide rows via hasResponse. Pages must tolerate missing fields.

localStorage keys

dsaHasVisited, dsaVisitorProfileComplete, dsaRace, dsaExperience, dsaBackgroundImage, dsaVotes|…, dsa-gas-score, DSA_TVT/PVP_QUIZ_SCORES, DSA_COMMUNITY_PATCHES_V3, DSA_SERVER_COMMUNITY_CACHE_V1(+_TS_), DSA_ADMIN_SESSION_V3, DSA_WORST_BUILD_VOTES_V1, DSA_DISABLE/ENABLE_PUBLIC_BACKEND_SYNC.
